# Security notes

Authentication uses Node scrypt (N=32768, r=8, p=1, random 128-bit salt, 64-byte derived key) and constant-time password comparison. Login performs a dummy derivation for unknown identities. Human provisioning requires a minimum 12-character password; there is no public registration or default admin password. Session secrets and CSRF tokens are 256-bit random values and are persisted only as SHA-256 hashes. Sessions expire after eight hours. Logout revokes the session server-side. Disabled identities fail all authentication.

The session cookie is HttpOnly, SameSite=Strict and Secure by default. Local HTTP Compose explicitly disables Secure; production HTTPS must enable it. Browser writes require X-CSRF-Token. Origin validation runs on every request that sends Origin, including login; CORS permits only the configured exact origin with credentials. SameSite=Strict and JSON-only bodies additionally protect login. Clients without Origin are permitted for CLI/MCP, with authentication still mandatory. `trustProxy` is false; configure proxy trust only after evaluating the actual deployment topology.

Each resource read and write checks membership in the parent project. Foreign IDs produce a non-enumerating 404. A nested resource also checks its own project ID. Viewers cannot mutate. Human-only endpoints reject service identities independently of scopes. Service tokens expire in 90 days and require explicit memberships plus per-operation scopes. Secrets are never returned by current-user responses. MCP/n8n gets HTTP tokens, never DATABASE_URL. Outbound N8N_TOKEN and inbound service token are separate credentials.

All SQL uses bound parameters; dynamic query fragments are fixed application code. Strict Zod schemas reject unknown fields, invalid UUIDs/enums/dates, contradictory dates, excessive lengths and unsupported references. Request bodies and adapter responses are limited to 1 MiB; plan drafts allow 50 phases and 500 tasks. Response schemas validate and remove unlisted fields. Errors expose a stable code and request UUID; internal database errors are sanitized. Request IDs are generated by the backend and reused by activity entries. Browser-supplied tracing headers cannot replace them.

Helmet supplies security headers. Requests have a 30-second HTTP timeout. General rate limit: 120 requests/minute/IP per backend process; login: 10/minute/IP. Statement timeout is 15 seconds. Multi-instance/shared rate limiting and per-account lockout are intentionally not implemented in this local foundation; deploying multiple replicas requires a shared limiter. Expired session and idempotency record retention is an operator policy; records are not silently deleted, preserving retry guarantees.

Plan content, approval rows, plan task drafts, and activity history are protected by database immutability triggers. An AI claim that a human approved has no effect: only a human session reaching the approval endpoint can create approval, bound to the exact saved hash. Human identity, membership, state and hash are also checked by a database insertion trigger. Publish rechecks approval and content hash under project/plan locks. Changed state requires a new version. Material task metadata is proposed rather than directly overwritten. Transactional idempotency plus publication state checks prevent duplicate published tasks.

The adapter uses only a configured fixed HTTP(S) URL; redirects are rejected, upstream calls time out after 15 seconds, and arbitrary model/request URLs are never fetched. Sanitized errors avoid storing upstream secrets. Durable operation retries are bounded. Upstream n8n must enforce its own token verification, payload validation and operation-ID deduplication. The backend cannot enforce security inside a workflow not provided in this repository.

The container runs as nonroot with a read-only filesystem, dropped capabilities and no-new-privileges. Local ports bind only to loopback. The Compose build context excludes .env files and host node_modules. Secrets come from ignored environment files or process environment, not tracked code. No production database, cloud resources or direct model calls are used.

Before any production release, separately design TLS ingress, runtime/migrator DB roles, backup/restore policy, operational access, token rotation, centralized monitoring and rate-limit storage. This assignment does not deploy or claim those controls exist.
