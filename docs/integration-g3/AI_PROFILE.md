## Profile and limits

`automation/n8n/ai-profile/G3AIWorkflow00001.json`–`00003.json` are reproducibly generated by `node scripts/integration-g3/ai/compile.mjs` from the original, credential-bearing workflow sources. They are not generated from the compiled deterministic profile. Each OpenAI model node keeps `openAiApi` credential reference `uapm-openai`.

The Coordinator, Planner and Reviewer each use one native Basic LLM Chain invocation connected to the original native OpenAI Chat Model node. This implements one pass per role, within the maximum three iterations, without tool calls, memory, self-repair, approval or publication authority. The Reviewer may accept or fail the proposal, never revise/approve/publish it. Local Code validators enforce exact allowed JSON fields, project scope, phases, task IDs, definitions of done and acyclic dependencies before the canonical MCP/backend validation. Unsupported owner/date fields fail closed.

| Control | Enforced bound |
| --- | --- |
| Model | `gpt-4.1-mini`, fixed; no environment override |
| Model calls | Three total across the real acceptance ledger's lifetime, at most one per operation/stage |
| Output | 1,200 tokens per call |
| Input | Entire provider request at most 12,000 UTF-8 bytes; UI planning goal at most 1,500 characters for this acceptance profile |
| Provider time | 10 seconds at the guard; native model timeout 12 seconds |
| Retry | Zero provider/model/node retries; crash/timeout reservation is never refunded |
| Overall budget | USD 0.01 reserved per attempted call, USD 0.03 maximum; request for owner authorization capped at USD 0.05 |
| Stage order | Coordinator → Planner → Reviewer; prior stage must have succeeded |
| Workflow | 55-second per-workflow timeout; entry immediately acknowledges with HTTP 202 |
| Credentials | Dedicated sandbox credential encrypted only in G3 n8n; never supplied to React |
| Provenance | Original operation ID, request ID, context hash and base are retained; model output supplies none of these |

The guard at loopback `23083` forwards only Chat Completions to the fixed official HTTPS endpoint. Its SQLite ledger `.g3/ai-budget.sqlite` is cost-control metadata, not a second domain database or migration. Transactional reservations commit before provider I/O; duplicate callbacks, backend retries, process crashes and restarts cannot reset them. It verifies the authoritative PostgreSQL operation, unchanged base/context hash and current human project membership before reserving. Backend revalidates again at callback/publication. Missing local expense authorization defaults to deny. The guard does not log credentials, prompts, provider bodies or provider error messages; evidence contains hashes, request/completion IDs, usage and safe status codes.

At the [official GPT-4.1 mini rates](https://developers.openai.com/api/docs/models/gpt-4.1-mini) checked 2026-10-29 (USD 0.40/M input, USD 1.60/M output), the input/output limits fit comfortably within each USD 0.01 reservation, including message framing. This is a local ceiling at these documented rates, not a provider-account spending cap. Review pricing and model availability before owner authorization; actual account/model access remains unverified. The official page marks the dated snapshot deprecated; this profile retains the existing model alias for compatibility and does not assume account availability.

The installed n8n 1.74.0 code was checked as well as the [model-node documentation](https://docs.n8n.io/integrations/builtin/cluster-nodes/sub-nodes/n8n-nodes-langchain.lmchatopenai/). Model-node version **1** is deliberate: version 1.1 hides its per-invocation Base URL option. The credential helper sets its fallback URL to local `/DENY` so configuration drift cannot silently send requests around the guard. The [webhook](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/) uses the version-2 nested custom-code format for HTTP 202, avoiding the existing backend adapter's 15-second deadline.
