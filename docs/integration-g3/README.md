# G3 isolated integration runtime

This branch combines the frozen backend, React frontend and MCP/n8n candidates. The backend OpenAPI v1.1.0 and P1 approval policy are unchanged. All examples use synthetic identities. This is local acceptance infrastructure, not a deployment.

Requirements: Node 24, npm, Docker Compose and Playwright Chromium. Run from the repository root. Keep browser URLs on **localhost** throughout a session.

```sh
npm --prefix apps/backend ci
npm --prefix apps/frontend ci
npm --prefix apps/mcp-server ci
npm --prefix apps/backend run build
npm --prefix apps/mcp-server run build
node scripts/integration-g3/bootstrap.mjs
docker compose --env-file .g3/runtime.env -f infra/integration-g3/compose.yaml up -d
node scripts/integration-g3/n8n-session.mjs
node scripts/integration-g3/import-workflows.mjs
```

The source n8n model configuration is capped at three agent iterations and 1,200 output tokens, but that AI path has not been executed.

The n8n-session helper initializes only the G3 synthetic owner (or logs into that existing account); it never resets an account.

The bootstrap creates random credentials in ignored `.g3/runtime.env` (mode 0600, directory 0700). Never copy them into a report, Vite configuration, chat or Git. If Chromium is missing, run `cd apps/backend && npx playwright install chromium`.

Start the following three commands in separate terminals:

```sh
node scripts/integration-g3/runtime.mjs backend
# After backend startup/migrations, initialize local synthetic identities:
node scripts/integration-g3/seed.mjs
node scripts/integration-g3/runtime.mjs mcp
node scripts/integration-g3/runtime.mjs frontend
```

Open http://localhost:25173. Synthetic owner email: `g3-owner@example.invalid`; password is `G3_HUMAN_PASSWORD` in the ignored runtime file. The API listens on localhost:23081, MCP on localhost:23082, dedicated n8n on localhost:25682, PostgreSQL on localhost:25439. Only this compose project's containers/volumes should be operated on. Nothing uses port 8100.

The G3 backend is configured with `AUTOMATION_SERVICE_ID`, generated by bootstrap and seeded as a dedicated service identity. Project creation atomically grants this configured identity editor membership and appends an audit event. The service's scopes remain read, plans:write, operations:write and plans:publish; it receives no human approval authority. If the configured identity is missing/ineligible, project creation fails atomically with 503. Unsetting the optional configuration preserves explicit manual membership for other installations. No database intervention occurs between React project creation and planning in the acceptance scenario.

The live plan workspace supports planning from an empty project, manual draft creation, immutable revisions, version selection, submit-review, exact-ID/hash human approval/rejection, publication, revocation history and pending operation polling. Task metadata proposals through MCP leave published tasks unchanged. Unsupported product fields remain explicit errors; backend failure never selects demo data.

The dedicated n8n profile uses the source workflows compiled without AI credential nodes. Coordinator, Planner and Reviewer use clearly marked deterministic fixtures; subsequent schema validation, MCP calls, backend callbacks and PostgreSQL persistence are real. Webhook bearer authentication is imported into this isolated n8n credential store from the ignored runtime file. Six stable workflow IDs make nested execution reproducible. `import-workflows.mjs` only imports into this dedicated instance. Reimport restarts that instance; do it before, not during, acceptance runs.

**Real AI mode remains NOT VERIFIED.** A separate bounded native AI profile is now available; see [AI setup and owner actions](AI_PROFILE.md) and [final acceptance](FINAL.md). Do not change `G3_PLANNING_MODE` to turn the compiled fixture graph into AI. Use `G3_EXECUTION_PROFILE=ai` only after the documented credential and expense gates. No credential was supplied or copied from another installation; no paid calls were made.

G3 MVP approval scope retains P1: permission-based revocation, explicit human revocation and credential expiry are supported/tested. Time-based approval TTL is out of scope, with Product Owner ratification required before final release acceptance. No migration or contract change implements a TTL.

## Repeatable verification

Run acceptance scripts sequentially; the unchanged API limits requests to 120/minute. Do not run intentional outage suites against the acceptance database. HTTP runner preserves its key while waiting on rate limits. The browser main scenario waits for a fresh rate window before starting the independent mobile browser.

```sh
node scripts/integration-g3/browser.mjs
node scripts/integration-g3/browser-retry.mjs
node scripts/integration-g3/http.mjs
# Allow the rate window to reset before the next browser run when necessary.
node scripts/integration-g3/browser-policy.mjs
node scripts/integration-g3/browser-errors.mjs
# Controlled outage: only G3 PostgreSQL is stopped/restarted; no concurrent runs.
node scripts/integration-g3/browser-outage.mjs
npm --prefix apps/frontend test
npm --prefix apps/frontend run build
npm --prefix apps/mcp-server test
npm --prefix apps/mcp-server run build
```

The browser scripts create fresh synthetic human identities and projects, use real React + HTTP + PostgreSQL, and write evidence under docs/integration-g3/evidence. They never claim an AI-model call. The HTTP script also invokes real WF-04, WF-05 (including exact-key replay) and WF-06. The main browser scenario executes WF-01 → WF-02 → WF-03.

For the complete backend suite, first create **uapm_test only inside uapm-g3-postgres-1**, then use the supplied runner; it passes a local-only TEST_DATABASE_URL and tests migrations/auth/concurrency/revocation/callback/recovery without resetting uapm_g3:

```sh
docker compose --env-file .g3/runtime.env -f infra/integration-g3/compose.yaml exec -T postgres createdb -U uapm uapm_test
node scripts/integration-g3/backend-tests.mjs
```

An existing test database is reusable; a second createdb may report already exists. This repository's packages expose typecheck/build and backend format:check rather than a lint script. No nonexistent lint command is reported as passed.

Shutdown: stop the three runtime terminals, then `docker compose --env-file .g3/runtime.env -f infra/integration-g3/compose.yaml stop`. Preserve the named volumes and `.g3` files to preserve synthetic acceptance history. Never use global Docker cleanup commands. No main merge or production deployment is authorized by this setup.

Collect execution and migration evidence with `node scripts/integration-g3/evidence.mjs`, then redact synthetic UUIDs for sharing with `node scripts/integration-g3/redact-evidence.mjs`. Run the collector before redaction; it uses the current browser scenario IDs. The original UUID evidence and alias map remain ignored locally.
